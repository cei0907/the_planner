Implementation Specification

DB Schema & API Contract

The Planner MVP 구현을 위한 MariaDB 스키마와 REST API 계약 요약 문서다. 원본은 docs/06-database-schema.md, docs/07-api-contract.md다.

1. 설계 원칙

  1. 모든 사용자 소유 데이터는 user_id를 가진다.
  2. Task와 Plan은 분리한다.
  3. Plan은 완료 상태를 가지지 않는다.
  4. Plan 화면의 체크 상태는 plan_tasks에 저장한다.
  5. Task Tree는 MVP에서 adjacency list 방식, 즉 tasks.parent_id로 표현한다.
  6. 진행률은 Leaf 기준 집계값으로 저장한다.
  7. 반복은 Task에 직접 넣지 않고 repeat_rules로 분리한다.

2. 핵심 테이블

users

단일 사용자 로그인부터 시작하되, 추후 팀 기능을 고려한다.

tasks

Task Tree, Task Type, 목표 기간, 완료 상태를 관리한다.

task_progress

Leaf 기준 진행률 집계값을 저장한다.

plans

시간 슬롯과 장소, 메모, 비용 같은 현장성 정보를 관리한다. 완료 상태는 없다.

plan_tasks

Plan에 연결된 Task와 Plan 화면 체크 상태를 관리한다.

plan_supplies

Plan에 필요한 준비물 체크리스트를 관리한다.

repeat_rules

반복 주기와 종료 조건을 관리한다.

repeat_occurrences

반복으로 생성된 개별 회차를 관리한다.

Plan 테이블 금지 필드

plans 테이블에는 다음 필드를 두지 않는다.

is_done
status
completed_at

3. 핵심 조회

특정 기간의 Plan 조회

SELECT *
FROM plans
WHERE user_id = ?
  AND deleted_at IS NULL
  AND start_at < ?
  AND end_at > ?
ORDER BY start_at ASC;

Plan에 연결된 Task 조회

SELECT pt.*, t.title, t.type, t.status AS task_status
FROM plan_tasks pt
JOIN tasks t ON t.id = pt.task_id
WHERE pt.plan_id = ?
ORDER BY pt.id ASC;

4. API 그룹

Auth

로그인과 현재 사용자 조회.

Task

Task CRUD, Tree 조회, 하위 Task 생성, 완료 전파.

Plan

Plan CRUD, 기간별 조회, 상세 조회.

PlanTask

Plan에 Task 연결, Leaf 자동 펼침, 체크/체크 해제.

PlanSupply

준비물 추가, 수정, 체크, 삭제.

RepeatRule

반복 규칙 생성, 조회, 수정, 삭제.

핵심 API 규칙

  1. Plan을 체크하는 API는 없다.
  2. 체크 API는 PlanTask를 대상으로 한다.
  3. 상위 Task를 Plan에 연결하면 하위 Leaf Task들이 PlanTask로 생성된다.
  4. Task 완료 API는 자기 자신과 하위 Task 전체에 완료를 전파한다.
  5. Task 완료 해제 API는 자기 자신만 미완료 처리한다.
