Life Planning System · 기획서 v2

인생설계 플래너 앱

큰 지향점과 프로젝트를 Task Tree로 구조화하고, 실제 시간 슬롯인 Plan에 연결해 오늘의 실행으로 내려오게 만드는 개인 플래너 시스템.

1. 프로젝트 개요

이 프로젝트는 단순 Todo 앱이나 캘린더 앱이 아니다. 사용자가 장기적인 지향점, 프로젝트, 할 일을 계층적으로 정리하고, 그것을 실제 시간 슬롯에 배치해 PC, 휴대폰, iPad 등 여러 기기에서 확인하고 수정하고 체크할 수 있게 만드는 인생설계 플래너다.

앱은 처음부터 멀티디바이스 사용을 전제로 한다. 카페24 VPS 같은 저비용 가상서버에 백엔드와 데이터베이스를 두고, 사용자는 PWA 형태로 브라우저에서 접속하거나 홈 화면에 설치해 앱처럼 사용한다.

큰 계획이 오늘의 시간으로 내려오는 플래너

2. 제품 철학

이 앱의 핵심은 의미와 시간을 분리한 뒤 다시 연결하는 것이다. 사람은 먼저 무엇을 하고 싶은지, 왜 해야 하는지를 생각한다. 그리고 나중에 그것을 언제, 어디서, 어떤 조건으로 실행할지 정한다.

Task 화면

그 일이 가지는 의미, 목적, 상위 맥락, 하위 구조를 보여준다. Task 화면은 What과 Why를 담당한다.

Plan 화면

그 시간에 해야 할 일, 장소, 준비물, 메모, 비용 같은 실행 맥락을 보여준다. Plan 화면은 When, Where, Context를 담당한다.

3. 핵심 개념

개념 의미 역할
Task 무엇을 할 것인가 목표, 작업, 프로젝트, 지향점을 계층 구조로 관리한다.
Plan 언제 어디서 실행할 것인가 특정 시간 슬롯과 현장성 정보를 관리한다. 자체 완료 상태는 갖지 않는다.
PlanTask Plan에 연결된 실행 Task 하나의 Plan 안에서 실제로 수행할 Task 목록을 관리한다.
RepeatRule 반복 배치 규칙 반복 Task의 Plan 인스턴스를 생성하거나 관리한다.
Progress 완료율 집계 Leaf Task 기준으로 상위 Task의 진행률을 계산한다.

4. Task 설계

Task는 이 앱의 의미 단위다. Task는 최대 5단계까지 계층 구조를 가질 수 있으며, 각 단계의 이름은 시스템이 강제하지 않는다. 사용자는 큰 지향점부터 작은 실행 항목까지 자유롭게 만들 수 있다.

Task Type

할 일 · task

가장 일반적인 실행 항목이다. 단독으로 존재할 수도 있고 프로젝트나 지향점 아래에 속할 수도 있다.

프로젝트 · project

여러 Task를 묶는 목표 단위다. 추후 팀 단위 운영으로 확장될 수 있다.

지향점 · aspiration

아직 실행 구조나 기간이 명확하지 않지만 삶의 방향성과 욕망을 담은 목표다.

Task 주요 속성

  • 제목, 설명, Why
  • Task Type: task, project, aspiration
  • 상위 Task, 하위 Task 목록
  • 레벨: 1부터 5까지
  • 목표 기간: 선택값
  • 상태: todo, active, done
  • 완료 여부
  • 중요도와 우선순위
  • 반복 여부
  • Leaf 집계값: 전체 Leaf 수, 완료 Leaf 수, 진행률

Leaf Task 원칙

실제 실행과 체크의 기본 단위는 Leaf Task다. Level1 Task라도 하위 Task가 없다면 Leaf Task가 될 수 있다. 반대로 Level5 Task는 항상 Leaf Task다.

상위 Task를 Plan에 배치하면, 시스템은 그 아래의 Leaf Task들을 자동으로 펼쳐 Plan에 추가한다. 상위 Task 자체는 의미 경로로 남고, 실제 실행은 Leaf Task 중심으로 진행한다.

5. Plan 설계

Plan은 특정 의미로 잘라낸 시간 슬롯이다. Plan은 완료 체크를 갖지 않는다. 완료는 Task 또는 PlanTask 수행 기록에서 관리한다.

Plan의 역할

  • 시작 일시와 종료 일시를 가진다.
  • 장소, 준비물 체크리스트, 메모, 비용을 가진다.
  • Task 없이 메모성 일정으로 존재할 수 있다.
  • 하나 이상의 Task를 연결할 수 있다.
  • Plan 화면에서는 그 시간에 해야 할 일과 현장 정보를 보여준다.

Plan 현장성 정보

장소

실행이 일어나는 위치나 이동 맥락을 기록한다.

준비물 체크리스트

현장에 가기 전 챙겨야 할 물건이나 확인 사항을 관리한다.

메모

상황별 참고 사항, 링크, 약속 내용, 주의점을 자유롭게 기록한다.

비용

예상 비용이나 실제 비용을 기록한다. 추후 장부, 가계부, 이벤트 비용 분석으로 확장할 수 있다.

6. 반복 설계

사용자는 같은 Task를 여러 시간 슬롯에 배치할 수 있다. 이미 배치된 Task를 다시 배치하려 할 때, 시스템은 반복으로 전환할지 제안할 수 있다. UX에서는 반복 Task처럼 보이지만, 내부 구조는 Task와 RepeatRule을 분리한다.

MVP 반복 규칙

  • 반복 주기: 매일, 매주, 매월, 매년
  • 반복 간격: 1일마다, 2주마다, 3개월마다 등
  • 주간 반복의 요일 선택
  • 종료 조건: 없음, 특정 날짜까지, N회 반복
  • 하위 Task가 있는 Task도 반복 가능
  • 하위 Task가 있는 반복 Task는 Plan에 Leaf Task들이 자동 반복 배치됨

반복 Task 완료 규칙

종료형 반복: N회 반복 또는 종료일이 있는 반복은 모든 회차가 완료되면 원본 Task도 done 처리된다.
습관형 반복: 종료 조건이 없는 반복은 원본 Task를 active 상태로 유지한다.
원본 Task를 직접 완료하면 남은 회차까지 완료 처리할지 확인한다.

7. 완료와 진행률

완료 체크 규칙

  • Task 완료 체크는 자기 자신과 모든 하위 Task를 done 처리한다.
  • 하위 Task가 많은 상위 Task를 완료할 때는 확인 모달을 띄운다.
  • Task 완료 해제는 기본적으로 자기 자신만 미완료로 바꾼다.
  • Plan 자체에는 done check가 없다.
  • PlanTask 완료는 해당 시간 슬롯에서의 수행 기록으로 남는다.

진행률 계산

상위 Task의 진행률은 Leaf Task 기준으로 계산한다. 즉 완료된 Leaf Task 수 / 전체 Leaf Task 수가 기본 계산식이다.

성능을 위해 각 Task는 leaf_total_count, leaf_done_count, progress_rate를 가진다. Leaf Task의 완료 상태가 바뀌면 전체 트리를 다시 계산하지 않고 조상 Task 경로만 위로 갱신한다.

8. 화면 구성

Plan 화면

Plan 화면은 연간, 월간, 주간, 일간 단위에 맞는 형태로 제공한다. 월간은 캘린더 형태를 지향하고, 주간과 일간은 시간대별 실행 흐름이 잘 보이게 구성한다.

  • 연간 화면: 큰 계획과 주요 기간을 조망
  • 월간 화면: 캘린더 기반 Plan 확인
  • 주간 화면: 한 주의 시간 배치와 집중 구간 확인
  • 일간 화면: 오늘의 시간 슬롯과 실행 Task 확인

Task 화면

Task 화면은 시간표가 아니라 의미 구조를 보여준다. 전체 Task Tree, 상위 경로, 하위 Task, 진행률, Why, 목표 기간을 관리한다.

  • Task Tree 펼치기와 접기
  • 하위 Task 생성
  • 최대 5단계 깊이 제한
  • Task Type 표시
  • Leaf 기준 진행률 표시
  • 상위 Task 완료 시 하위 Task 전체 완료

Task List 화면

연간, 월간, 주간, 일간 Task 목록을 시간과 별개로 리스트로 볼 수 있게 한다. 이는 기간별 ToDo List 역할을 한다.

9. 데이터 모델 초안

테이블 주요 필드 설명
users id, email, password_hash, display_name 초기에는 단일 사용자 로그인을 지원하되, 추후 팀 기능을 고려한다.
tasks id, user_id, parent_id, type, title, description, why, level, status, target_start_at, target_end_at Task Tree와 의미 구조를 관리한다.
task_progress task_id, leaf_total_count, leaf_done_count, progress_rate Leaf 기준 진행률 집계를 관리한다.
plans id, user_id, title, start_at, end_at, location, memo, estimated_cost, actual_cost 시간 슬롯과 현장 정보를 관리한다.
plan_tasks id, plan_id, task_id, status, completed_at Plan에 연결된 Task와 해당 슬롯의 수행 상태를 관리한다.
plan_supplies id, plan_id, title, is_checked Plan별 준비물 체크리스트를 관리한다.
repeat_rules id, task_id, frequency, interval_value, weekdays, end_type, end_at, occurrence_count 반복 배치 규칙을 관리한다.

10. 기술 방향

Frontend

React 기반 PWA. PC, 휴대폰, iPad에서 브라우저 접속과 홈 화면 설치를 지원한다.

Backend

Node.js와 Express 기반 API. 인증, Task, Plan, 반복, 진행률 계산을 담당한다.

Database

MariaDB. 카페24 VPS 같은 저비용 서버에서 운영 가능하도록 설계한다.

단일 사용자 로그인 PWA 설치 MariaDB React Express 5분 단위 UI

12. 확장 방향

  • AI 추천: 하위 Task 후보, 준비물, Plan에 어울리는 Task를 추천하되 자동 확정하지 않는다.
  • 팀 기능: Project를 팀 단위로 공유하고 역할과 권한을 부여한다.
  • 장부 연결: Plan 비용을 Expense 객체로 확장해 이벤트 기반 가계부로 연결한다.
  • 오프라인 지원: PWA 캐시와 임시 저장으로 네트워크가 불안정한 상황을 보완한다.
  • 통계: 지향점, 프로젝트, 기간별 실행률과 비용 흐름을 시각화한다.
