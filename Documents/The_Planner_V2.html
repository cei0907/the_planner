Life Planning System · 기획서 v2 확장판

인생설계 플래너 앱

큰 지향점과 프로젝트를 Task Tree로 구조화하고, 실제 시간 슬롯인 Plan에 연결해 오늘의 실행으로 내려오게 만드는 개인 플래너 시스템.

1. 프로젝트 개요

이 프로젝트는 단순 Todo 앱이나 일반 캘린더 앱이 아니다. 사용자가 장기적인 지향점, 프로젝트, 할 일을 계층적으로 정리하고, 그것을 실제 시간 슬롯에 배치해 PC, 휴대폰, iPad 등 여러 기기에서 확인하고 수정하고 체크할 수 있게 만드는 인생설계 플래너다.

초기 버전부터 멀티디바이스 사용을 전제로 한다. 카페24 VPS 같은 저비용 가상서버에 백엔드와 MariaDB를 두고, 사용자는 PWA 형태로 브라우저에서 접속하거나 홈 화면에 설치해 앱처럼 사용한다.

기존 기획서 v1은 Task를 중심으로 연간, 월간, 주간, 일간 배치를 다루었다. v2에서는 대화를 통해 Task와 Plan을 분리한다. Task는 의미와 구조를 담당하고, Plan은 시간과 현장 맥락을 담당한다.

큰 계획이 오늘의 시간으로 내려오는 플래너

2. 제품 철학

사람은 먼저 무엇을 하고 싶은지, 왜 해야 하는지를 생각한다. 그리고 나중에 그것을 언제, 어디서, 어떤 조건으로 실행할지 정한다. 이 앱은 그 두 과정을 섞지 않고 분리한 뒤, 필요할 때 다시 연결한다.

Task 화면

그 일이 가지는 의미, 목적, 상위 맥락, 하위 구조를 보여준다. Task 화면은 What과 Why를 담당한다.

Plan 화면

그 시간에 해야 할 일, 장소, 준비물, 메모, 비용 같은 실행 맥락을 보여준다. Plan 화면은 When, Where, Context를 담당한다.

Plan 화면에서는 그 시간에 해야 할 일을 보여주고, Task 화면에서는 그 일이 의미하는 구조와 방향을 보여준다. 이 분리가 이 시스템의 가장 중요한 설계 원칙이다.

3. 핵심 개념

개념 의미 역할
Task 무엇을 할 것인가 목표, 작업, 프로젝트, 지향점을 계층 구조로 관리한다.
Plan 언제 어디서 실행할 것인가 특정 시간 슬롯과 현장성 정보를 관리한다. 자체 완료 상태는 갖지 않는다.
PlanTask Plan에 연결된 실행 Task 하나의 Plan 안에서 실제로 수행할 Task 목록을 관리한다.
RepeatRule 반복 배치 규칙 반복 Task의 Plan 인스턴스를 생성하거나 관리한다.
Progress 완료율 집계 Leaf Task 기준으로 상위 Task의 진행률을 계산한다.

Task와 Plan의 분리 예시

사용자가 공무원 시험 준비라는 큰 목표를 만든다고 해서, 그 목표 자체가 바로 일정이 되는 것은 아니다. 이 목표는 Task Tree 안에서 의미 구조를 가진다. 이후 사용자는 2026-07-08 09:00~11:00 Plan을 만들고, 그 시간 슬롯에 1강 듣기, 1강 쉐도잉하기 같은 Leaf Task를 연결한다.

반대로 오늘 은행가기처럼 세부 계획이 거의 필요 없는 일은 Level1 Task이면서 동시에 Leaf Task가 될 수 있다. 이 Task를 2026-06-30 14:00~16:00 Plan에 연결하면, 별도의 하위 Task 없이 바로 실행 항목이 된다.

4. Task 설계

Task는 이 앱의 의미 단위다. Task는 최대 5단계까지 계층 구조를 가질 수 있으며, 각 단계의 이름은 시스템이 강제하지 않는다. 사용자는 큰 지향점부터 작은 실행 항목까지 자유롭게 만들 수 있다.

Task Type

할 일 · task

가장 일반적인 실행 항목이다. 단독으로 존재할 수도 있고 프로젝트나 지향점 아래에 속할 수도 있다.

프로젝트 · project

여러 Task를 묶는 목표 단위다. 추후 팀 단위 운영으로 확장될 수 있다.

지향점 · aspiration

아직 실행 구조나 기간이 명확하지 않지만 삶의 방향성과 욕망을 담은 목표다.

Task 주요 속성

  • 제목, 설명, Why
  • Task Type: task, project, aspiration
  • 상위 Task, 하위 Task 목록
  • 레벨: 1부터 5까지
  • 목표 기간: 선택값
  • 상태: todo, active, done
  • 완료 여부
  • 중요도와 우선순위
  • 반복 여부
  • Leaf 집계값: 전체 Leaf 수, 완료 Leaf 수, 진행률

Leaf Task 원칙

실제 실행과 체크의 기본 단위는 Leaf Task다. Level1 Task라도 하위 Task가 없다면 Leaf Task가 될 수 있다. 반대로 Level5 Task는 항상 Leaf Task다.

상위 Task를 Plan에 배치하면, 시스템은 그 아래의 Leaf Task들을 자동으로 펼쳐 Plan에 추가한다. 상위 Task 자체는 의미 경로로 남고, 실제 실행은 Leaf Task 중심으로 진행한다.

Task Tree 예시

Lv1 프로젝트: 공무원 시험 준비
Lv2 할 일 묶음: 영어 공부
Lv3 세부 분야: 리스닝
Lv4 실행 묶음: 기초 리스닝 강의 듣기
Lv5 Leaf Task: 1강 듣기, 1강 쉐도잉하기

같은 구조에서 리스닝을 완료 체크하면 기초 리스닝 강의 듣기, 1강 듣기, 1강 쉐도잉하기 등 모든 하위 Task가 함께 완료 처리된다. 단, 상위 Task의 진행률은 Leaf Task 완료 수를 기준으로 계산한다.

지향점 예시

유럽에서 한 달 살아보기 같은 항목은 당장 일정이나 실행 구조가 정해지지 않았을 수 있다. 이 경우 Task Type을 aspiration으로 두고, Why와 메모를 먼저 기록한다. 나중에 실제 실행 가능성이 생기면 프로젝트로 전환하거나 하위 Task를 추가한다.

5. Plan 설계

Plan은 특정 의미로 잘라낸 시간 슬롯이다. Plan은 완료 체크를 갖지 않는다. 완료는 Task 또는 PlanTask 수행 기록에서 관리한다.

Plan의 역할

  • 시작 일시와 종료 일시를 가진다.
  • 장소, 준비물 체크리스트, 메모, 비용을 가진다.
  • Task 없이 메모성 일정으로 존재할 수 있다.
  • 하나 이상의 Task를 연결할 수 있다.
  • Plan 화면에서는 그 시간에 해야 할 일과 현장 정보를 보여준다.

Plan 현장성 정보

장소

실행이 일어나는 위치나 이동 맥락을 기록한다.

준비물 체크리스트

현장에 가기 전 챙겨야 할 물건이나 확인 사항을 관리한다.

메모

상황별 참고 사항, 링크, 약속 내용, 주의점을 자유롭게 기록한다.

비용

예상 비용이나 실제 비용을 기록한다. 추후 장부, 가계부, 이벤트 비용 분석으로 확장할 수 있다.

Plan과 Task 연결 규칙

  • Plan은 Task 없이 존재할 수 있다. 예: 치과 예약, 친구와 약속, 단순 메모 일정.
  • Plan은 여러 Task를 가질 수 있다. 예: 여행 준비 Plan 안에 교통편 확인, 짐 챙기기, 예약 확인을 연결.
  • Plan에서 Task를 검색할 때는 Plan 시간 범위와 Task 목표 기간이 겹치는 항목을 우선 노출한다.
  • 기간이 없는 지향점이나 Task는 기본 검색에서는 덜 강조하고, 필터로 포함할 수 있게 한다.
  • 상위 Task를 선택하면 그 하위 Leaf Task들이 PlanTask로 자동 추가된다.

장기 시간 슬롯 예시

Plan은 하루 안에 끝나는 일정만 다루지 않는다. 월요일 15:30에 시작해 수요일 17:50에 끝나는 일정처럼 여러 날짜를 가로지르는 시간 범위도 표현할 수 있어야 한다. 따라서 Plan은 단순 날짜 필드가 아니라 start_at과 end_at을 기준으로 저장한다.

6. 반복 설계

사용자는 같은 Task를 여러 시간 슬롯에 배치할 수 있다. 이미 배치된 Task를 다시 배치하려 할 때, 시스템은 반복으로 전환할지 제안할 수 있다. UX에서는 반복 Task처럼 보이지만, 내부 구조는 Task와 RepeatRule을 분리한다.

MVP 반복 규칙

  • 반복 주기: 매일, 매주, 매월, 매년
  • 반복 간격: 1일마다, 2주마다, 3개월마다 등
  • 주간 반복의 요일 선택
  • 종료 조건: 없음, 특정 날짜까지, N회 반복
  • 하위 Task가 있는 Task도 반복 가능
  • 하위 Task가 있는 반복 Task는 Plan에 Leaf Task들이 자동 반복 배치됨

반복 Task 완료 규칙

종료형 반복: N회 반복 또는 종료일이 있는 반복은 모든 회차가 완료되면 원본 Task도 done 처리된다.
습관형 반복: 종료 조건이 없는 반복은 원본 Task를 active 상태로 유지한다.
원본 Task를 직접 완료하면 남은 회차까지 완료 처리할지 확인한다.

반복 배치 UX

사용자가 이미 Plan에 배치한 Task를 다른 날짜나 시간에 다시 배치하려 하면, 시스템은 반복으로 전환할지 제안한다. 단, 사용자가 원하지 않으면 단순히 별도의 PlanTask로 추가할 수 있다.

이미 배치된 Task입니다. 반복 Task로 설정할까요?

7. 완료와 진행률

완료 체크 규칙

  • Task 완료 체크는 자기 자신과 모든 하위 Task를 done 처리한다.
  • 하위 Task가 많은 상위 Task를 완료할 때는 확인 모달을 띄운다.
  • Task 완료 해제는 기본적으로 자기 자신만 미완료로 바꾼다.
  • Plan 자체에는 done check가 없다.
  • PlanTask 완료는 해당 시간 슬롯에서의 수행 기록으로 남는다.

완료 전파 상세 규칙

  1. 특정 Task를 완료 처리하면 자기 자신은 done 상태가 된다.
  2. 해당 Task의 모든 하위 Task도 done 상태가 된다.
  3. 전파 범위는 선택한 Task의 하위 Tree에만 적용된다.
  4. 형제 Task에는 영향을 주지 않는다.
  5. 상위 Task의 진행률은 하위 Leaf Task 상태를 기준으로 다시 계산된다.
  6. 완료 해제는 기본적으로 선택한 Task 자기 자신만 미완료 처리한다.
  7. 하위 Task까지 해제하는 기능은 추후 선택 옵션으로 확장할 수 있다.

진행률 계산

상위 Task의 진행률은 Leaf Task 기준으로 계산한다. 즉 완료된 Leaf Task 수 / 전체 Leaf Task 수가 기본 계산식이다.

성능을 위해 각 Task는 leaf_total_count, leaf_done_count, progress_rate를 가진다. Leaf Task의 완료 상태가 바뀌면 전체 트리를 다시 계산하지 않고 조상 Task 경로만 위로 갱신한다. 이는 세그먼트 트리식 집계 감각과 비슷하다.

8. 주요 사용 흐름

시나리오 1: 큰 지향점을 프로젝트로 발전시키기

사용자는 경제적으로 자유로워지기라는 지향점을 만든다. 처음에는 Why와 메모만 기록한다. 시간이 지나 구체적인 실행 의지가 생기면 이를 프로젝트로 전환하고, 수입원 만들기, 지출 구조 파악, 투자 공부 같은 하위 Task를 추가한다.

시나리오 2: 당일치기 여행 준비

사용자는 당일치기 여행이라는 프로젝트를 만들고, 그 아래에 교통편 확인, 맛집 후보 정리, 카메라 충전, 예약 확인 같은 하위 Task를 둔다. 이후 2026-07-04 08:00~22:00 Plan을 만들고 이 프로젝트를 연결한다. Plan에는 Leaf Task들이 자동으로 펼쳐진다.

이 Plan에는 장소, 준비물, 예상 비용, 메모를 함께 기록한다. 예를 들어 준비물에는 신분증, 보조배터리, 우산이 들어가고, 비용에는 교통비와 식비 예상액이 들어간다.

시나리오 3: 단독 Leaf Task 배치

사용자는 오늘 은행가기라는 Level1 Task를 만든다. 이 Task에는 하위 Task가 없으므로 Leaf Task다. 사용자는 2026-06-30 14:00~16:00 Plan을 만들고 이 Task를 연결한다. Plan 화면에서는 은행 위치, 준비물, 메모가 함께 보인다.

시나리오 4: 반복형 운동 Task

사용자는 30일 동안 아침 운동하기 Task를 만들고 매일 오전 7시에 반복되도록 설정한다. 반복 종료 조건은 30회다. 각 날짜의 PlanTask를 완료할 때마다 회차 완료 수가 증가하고, 30회가 모두 완료되면 원본 Task도 done 처리된다.

시나리오 5: 습관형 반복 Task

사용자는 매주 일요일 회고하기 Task를 만든다. 종료 조건이 없으므로 이 Task는 done으로 끝나는 목표가 아니라 active 상태로 유지되는 습관이다. 앱은 이번 달 수행률, 최근 4주 수행률 같은 방식으로 상태를 보여줄 수 있다.

9. 화면 구성

Plan 화면

Plan 화면은 연간, 월간, 주간, 일간 단위에 맞는 형태로 제공한다. 월간은 캘린더 형태를 지향하고, 주간과 일간은 시간대별 실행 흐름이 잘 보이게 구성한다.

  • 연간 화면: 큰 계획과 주요 기간을 조망
  • 월간 화면: 캘린더 기반 Plan 확인
  • 주간 화면: 한 주의 시간 배치와 집중 구간 확인
  • 일간 화면: 오늘의 시간 슬롯과 실행 Task 확인

Task 화면

Task 화면은 시간표가 아니라 의미 구조를 보여준다. 전체 Task Tree, 상위 경로, 하위 Task, 진행률, Why, 목표 기간을 관리한다.

  • Task Tree 펼치기와 접기
  • 하위 Task 생성
  • 최대 5단계 깊이 제한
  • Task Type 표시
  • Leaf 기준 진행률 표시
  • 상위 Task 완료 시 하위 Task 전체 완료

Task List 화면

연간, 월간, 주간, 일간 Task 목록을 시간과 별개로 리스트로 볼 수 있게 한다. 이는 기간별 ToDo List 역할을 한다.

모바일과 PC 대응

PC에서는 넓은 화면을 활용해 Task Tree, Plan 상세, 선택된 기간의 목록을 함께 볼 수 있다. 모바일에서는 한 화면에 하나의 목적만 보여준다. 오늘의 Plan, Task 상세, 준비물 체크, 기간 선택 같은 화면을 명확히 분리한다.

10. 데이터 모델 초안

테이블 주요 필드 설명
users id, email, password_hash, display_name 초기에는 단일 사용자 로그인을 지원하되, 추후 팀 기능을 고려한다.
tasks id, user_id, parent_id, type, title, description, why, level, status, target_start_at, target_end_at Task Tree와 의미 구조를 관리한다.
task_progress task_id, leaf_total_count, leaf_done_count, progress_rate Leaf 기준 진행률 집계를 관리한다.
plans id, user_id, title, start_at, end_at, location, memo, estimated_cost, actual_cost 시간 슬롯과 현장 정보를 관리한다.
plan_tasks id, plan_id, task_id, status, completed_at Plan에 연결된 Task와 해당 슬롯의 수행 상태를 관리한다.
plan_supplies id, plan_id, title, is_checked Plan별 준비물 체크리스트를 관리한다.
repeat_rules id, task_id, frequency, interval_value, weekdays, end_type, end_at, occurrence_count 반복 배치 규칙을 관리한다.

11. 기술 방향

Frontend

React 기반 PWA. PC, 휴대폰, iPad에서 브라우저 접속과 홈 화면 설치를 지원한다.

Backend

Node.js와 Express 기반 API. 인증, Task, Plan, 반복, 진행률 계산을 담당한다.

Database

MariaDB. 카페24 VPS 같은 저비용 서버에서 운영 가능하도록 설계한다.

단일 사용자 로그인 PWA 설치 MariaDB React Express 5분 단위 UI

13. 확장 방향

  • AI 추천: 하위 Task 후보, 준비물, Plan에 어울리는 Task를 추천하되 자동 확정하지 않는다.
  • 팀 기능: Project를 팀 단위로 공유하고 역할과 권한을 부여한다.
  • 장부 연결: Plan 비용을 Expense 객체로 확장해 이벤트 기반 가계부로 연결한다.
  • 오프라인 지원: PWA 캐시와 임시 저장으로 네트워크가 불안정한 상황을 보완한다.
  • 통계: 지향점, 프로젝트, 기간별 실행률과 비용 흐름을 시각화한다.
